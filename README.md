# Детекция объектов дорожной сцены на базе YOLOv8n

Исследовательский проект выпускной квалификационной работы бакалавра МГТУ им. Н. Э. Баумана **«Оптический нейросетевой классификатор в составе системы помощи водителю»**. В репозитории собраны Jupyter-ноутбуки по подготовке датасета KITTI, исследованию R-CNN, обучению и оценке YOLOv8n, а также экспериментальному экспорту модели в ONNX с квантованием INT8.

**Задача:** находить и классифицировать участников дорожного движения на изображениях с автомобильной камеры. Основной путь разработки — компактный детектор YOLOv8n; R-CNN представлен как отдельный исследовательский эксперимент.

## Что сделано

- Преобразована разметка KITTI в формат YOLO; изображения разделены на обучающую и валидационную выборки.
- Реализована аугментация для уменьшения дисбаланса классов.
- Обучены базовая и расширенная конфигурации YOLOv8n; исследованы разные разрешения входного изображения.
- Рассчитаны Precision, Recall, mAP50 и mAP50–95; подготовлен код для дополнительных графиков Pd/Pfa/DET.
- Выполнен экспериментальный экспорт в ONNX и квантование весов в INT8 с прицелом на встраиваемую платформу.

## Результаты

| Эксперимент | Precision | Recall | mAP50 | mAP50–95 |
| --- | ---: | ---: | ---: | ---: |
| Базовая YOLOv8n, последняя сохранённая эпоха обучения | 81,0 % | 64,1 % | 74,6 % | 49,7 % |
| YOLOv8n после обучения с расширенной аугментацией, отдельная валидация | **85,5 %** | **78,2 %** | **85,9 %** | **60,1 %** |

В обоих сохранённых выводах указана валидационная выборка из **1 497 изображений и 8 231 объекта**; размер входа — 640 пикселей. Значения взяты из выводов [`train_base_yolo.ipynb`](train_base_yolo.ipynb) и [`evaluation_model.ipynb`](evaluation_model.ipynb). Это результаты двух сохранённых запусков: настройки валидации в них различаются, поэтому таблицу не следует трактовать как строго контролируемое сравнение влияния аугментации.

В [`export_to_ONNX.ipynb`](export_to_ONNX.ipynb) сохранён результат уменьшения ONNX-файла с **11,70 до 3,31 МиБ**. Подсчёт INT8-тензоров в этом файле даёт **3 043 667 байт (~2,90 МиБ)**. Размер файла, объём тензоров и требуемая память при исполнении — разные величины; работоспособность модели на микроконтроллере этими числами не подтверждена.

## Данные и классы

Источник данных — [KITTI Object Detection Benchmark](https://www.cvlibs.net/datasets/kitti/eval_object.php?obj_benchmark=2d). В ноутбуке подготовки используются **7 481 размеченное изображение**: 5 984 для обучения и 1 497 для валидации. `DontCare` исключается, `Person_sitting` объединяется с `Pedestrian`. Для обучающей части в сохранённом выводе создано **40 400 аугментированных файлов разметки**.

После перенумерации классов в конце ноутбука подготовки ожидается следующий порядок в конфигурации YOLO:

| ID | Класс | ID | Класс |
| ---: | --- | ---: | --- |
| 0 | Car | 1 | Cyclist |
| 2 | Truck | 3 | Misc |
| 4 | Pedestrian | 5 | Van |
| 6 | Tram | | |

Для файла конфигурации датасета используйте `names: [Car, Cyclist, Truck, Misc, Pedestrian, Van, Tram]` и проверьте, что эти ID совпадают с ID в итоговых `.txt`. Генерация YAML и перенумерация меток в ноутбуке выполнены разными ячейками: автоматически созданный YAML требует проверки перед обучением.

## Как изучить или повторить эксперимент

1. Клонируйте репозиторий и установите [Python](https://www.python.org/) с Jupyter. Установите PyTorch и Torchvision согласно [инструкции для вашей платформы](https://pytorch.org/get-started/locally/), затем зависимости ноутбуков: `ultralytics`, `albumentations`, `opencv-contrib-python`, `scikit-learn`, `seaborn`, `matplotlib`, `PyYAML`, `onnx` и `onnxruntime`.
2. Откройте проект в Jupyter и выполните [`data_preprocessing_kitti.ipynb`](data_preprocessing_kitti.ipynb). Ноутбук загружает KITTI через `torchvision.datasets.Kitti` в `data/Kitti/raw` и готовит данные в `data/kitti_for_yolo/`.
3. Проверьте соответствие изображений и аннотаций по именам файлов, ID классов и `names` в YAML. Задайте реальные пути к датасету и начальным весам в ноутбуках обучения: локальные файлы `models/**/*.yaml` и `models/**/*.pt`, на которые они ссылаются, в репозиторий не загружены.
4. Запустите [`train_base_yolo.ipynb`](train_base_yolo.ipynb) или [`train_yolo_augmented.ipynb`](train_yolo_augmented.ipynb), настроив `device` и `batch` под своё оборудование. Для оценки укажите путь к полученному `best.pt` и YAML в [`evaluation_model.ipynb`](evaluation_model.ipynb).
5. Для эксперимента с экспортом укажите путь к `best.pt` в [`export_to_ONNX.ipynb`](export_to_ONNX.ipynb). [`R-CNN.ipynb`](R-CNN.ipynb) запускается отдельно; selective search требует сборки OpenCV с модулем `ximgproc`.

Ноутбуки сохраняют историю разработки, поэтому в них есть локальные пути, установки пакетов из ячеек и ссылки на промежуточные артефакты. Перед повторным запуском их нужно адаптировать под свою среду. Исходные данные KITTI, файлы весов и готовые YAML-конфигурации в репозитории отсутствуют.

### Ограничения экспорта

Экспорт в INT8 — **эксперимент**, а не подтверждённая прошивка для STM32. В сохранённом запуске для калибровки использовались случайно сгенерированные входные массивы; часть FP32-тензоров переводилась в INT8 принудительно. Вывод ноутбука также указывает на операторы, требующие проверки совместимости с STM32Cube.AI. Перед применением на устройстве необходимы калибровка на реальных изображениях, проверка корректности ONNX, повторная оценка качества после квантования и тестирование на целевой плате.
